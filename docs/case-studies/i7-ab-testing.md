## A. Problem statement

An online store tested a redesigned product page (variant B) against the current page
(variant A). Sessions were assigned at random. Variant B converted 10.3 % against 7.9 % for
A — a 30 % relative improvement. The product manager wants to ship B immediately. The
analyst must decide whether the evidence supports that, what the uncertainty is, and what
sample size the next test needs.

## B. Background and context

A/B testing is the gold standard for causal questions about product changes, precisely
because random assignment breaks the link between user characteristics and the treatment.
But a test can be randomised and still inconclusive. The two failures that dominate
practice are peeking (repeated testing until significance) and underpowered tests whose
null results are misread as "no effect". This case walks through a realistic result — a
promising but non-significant lift — and shows how to report it properly.

## C. Dataset description

`ab_test.csv` has 800 rows.

| Column | Type | Description |
|---|---|---|
| `session_id` | integer | 1–800 |
| `variant` | text | `A` (403 sessions) or `B` (397) |
| `device` | text | `desktop` (45 %) or `mobile` (55 %) |
| `converted` | integer | 1 if the session ended in a purchase |
| `session_seconds` | integer | Time on site |

**Generation method.** Variant is assigned by a fair coin, independent of device. The
conversion log-odds are \(-2.6+0.28\cdot\mathbf{1}[B]-0.25\cdot\mathbf{1}[\text{mobile}]\),
so B has a true relative lift of about 32 % overall and mobile converts less in both
variants. Because the sample is only 800 sessions, the realised difference is smaller than
the true one and not statistically significant — which is the teaching point.

## D. Questions to investigate

1. What are the conversion rates in A and B, with intervals?

3. Is the difference statistically significant?
4. Is the result consistent across desktop and mobile?
5. What sample size would detect a 1.4 pp absolute lift with 80 % power?
6. What is the power of this experiment for the effect it actually observed?

## F. Mathematical formulation

Rates and difference:

\[
\hat p_B-\hat p_A,\qquad
\mathrm{SE}=\sqrt{\frac{\hat p_A(1-\hat p_A)}{n_A}+\frac{\hat p_B(1-\hat p_B)}{n_B}}.
\]

Pooled test statistic under \(H_0:p_A=p_B\):

\[
z=\frac{\hat p_B-\hat p_A}{\sqrt{\bar p(1-\bar p)\left(\frac{1}{n_A}+\frac{1}{n_B}\right)}}.
\]

Sample size for a two-sided test with power \(1-\beta\) and effect
\(h=2\arcsin\sqrt{p_B}-2\arcsin\sqrt{p_A}\):

\[
n \approx \left(\frac{z_{1-\alpha/2}+z_{1-\beta}}{h}\right)^2 \text{ per arm}.
\]

## G. Step-by-step analytical approach

1. Check randomisation: are the arm sizes and device mixes similar?
2. Compute rates with Wilson intervals.
3. Compute the difference with a 95 % interval and a two-proportion z-test.
4. Confirm with a chi-square test and note that it agrees.
5. Examine device subgroups; discuss multiplicity and Simpson's paradox.
6. Compute the required sample size for the target effect.
7. Compute the experiment's power for the observed effect.
8. Write the decision with an explicit statement of what is and is not known.

## I. Python practical implementation

```python
import numpy as np
import pandas as pd
from scipy import stats
from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize

ab = pd.read_csv("docs/data/case-studies/ab_test.csv")
print(ab.head(3).to_string(index=False))
print("sessions:", len(ab), "| arms:", ab.variant.value_counts().to_dict())
print("device mix by arm:")
print(pd.crosstab(ab.variant, ab.device, normalize="index").round(3).to_string())

summary = ab.groupby("variant").converted.agg(["sum", "size", "mean"])
summary.columns = ["conversions", "sessions", "rate"]
print("\n", summary.round(4).to_string())

p_a, p_b = summary.loc["A", "rate"], summary.loc["B", "rate"]
n_a, n_b = int(summary.loc["A", "sessions"]), int(summary.loc["B", "sessions"])
diff = p_b - p_a
se = np.sqrt(p_a * (1 - p_a) / n_a + p_b * (1 - p_b) / n_b)
print(f"\ndifference = {diff:+.4f} ({diff:+.2%}), 95% CI "
      f"[{diff - 1.96 * se:+.4f}, {diff + 1.96 * se:+.4f}]")
print(f"relative lift = {diff / p_a:+.1%}")

pooled = (summary.conversions.sum()) / (n_a + n_b)
z = diff / np.sqrt(pooled * (1 - pooled) * (1 / n_a + 1 / n_b))
print(f"pooled z = {z:.3f}, p = {2 * (1 - stats.norm.cdf(abs(z))):.4f}")
print("chi-square:", [round(float(x), 3) for x in stats.chi2_contingency(
    pd.crosstab(ab.variant, ab.converted))[:2]])

print("\nby device:")
print(ab.groupby(["device", "variant"]).converted.agg(["mean", "size"]).round(4).to_string())

effect = proportion_effectsize(0.045, 0.031)
n_needed = NormalIndPower().solve_power(effect_size=effect, alpha=0.05, power=0.8)
power_now = NormalIndPower().power(effect_size=effect, nobs1=n_a, alpha=0.05)
power_observed = NormalIndPower().power(
    effect_size=proportion_effectsize(0.1033, 0.0794), nobs1=n_a, alpha=0.05)
print(f"\nsessions per arm for 1.4pp lift at 80% power: {n_needed:,.0f}")
print(f"power of this test for that effect: {power_now:.2f}")
print(f"post-hoc power for the observed effect: {power_observed:.2f}")

ci_low, ci_high = diff - 1.96 * se, diff + 1.96 * se
print(f"\nminimum lift consistent with the data: {ci_low / p_a:+.1%} relative")
```

**How to read it.** The bars differ by 2.4 percentage points, but the error bars are each
about ±1.9 points, so the intervals overlap substantially. The point estimate favours B,
and the interval for the difference runs from −1.6 to +6.4 points — it includes zero and
also includes a doubling of the effect. The data are compatible with "B is worse" and with
"B is much better".

## K. Expected conclusions

- A converted 7.94 % (32 of 403); B converted 10.33 % (41 of 397).
- The difference is +2.39 pp (95 % CI −1.60 to +6.38 pp); relative lift +30.1 %.
- z = 1.17, p = 0.241; chi-square 1.10, p = 0.294. Not significant at 5 %.
- The pattern holds in both device groups (desktop 11.9 %→13.9 %, mobile 4.9 %→7.1 %), so
  the direction is consistent even though neither subgroup is individually significant.
- The test had only 18 % power to detect a 1.4 pp lift, and about 22 % power for the
  observed effect: it was far too small.
- Detecting a 1.4 pp lift with 80 % power needs about 2,900 sessions per arm.
- The honest decision is "promising, not proven": continue the test to a pre-registered
  sample size rather than shipping on a 30 % point estimate.

## L. Detailed solution and discussion

**Step 1 — randomisation check.** Arms are 403 and 397, and the device mix is 54–55 %
mobile in both, so randomisation worked. If the arms had differed in device mix, the
comparison would be confounded: mobile converts at about 5–7 % and desktop at 12–14 %, so a
10-point imbalance in device share would create a spurious 0.7 pp difference on its own.

**Step 2 — rates and uncertainty.** A: 32/403 = 7.94 %, Wilson interval 5.68–10.99 %.
B: 41/397 = 10.33 %, interval 7.70–13.71 %. The intervals overlap heavily. Overlapping
intervals do not by themselves prove non-significance, but here the formal test agrees.

**Step 3 — the test.** Difference 2.39 pp; standard error 2.04 pp (the rates are small and
the samples are ~400 each). z = 1.17, two-sided p = 0.24. The 95 % interval is −1.60 to
+6.38 pp, so the data are consistent with B being 20 % worse (relative to A) and with B
being 80 % better. This is the correct way to report a null result: not "no difference" but
"a wide range of differences remains plausible".

**Step 4 — power.** With p_A ≈ 0.079 and 400 sessions per arm, the standard error is about
2 pp, so only differences above roughly 4 pp (about 50 % relative) would be detected at 80 %
power. The observed 2.4 pp lift is below the minimum detectable effect. Post-hoc power for
the observed effect is 0.22, but post-hoc power is a monotone transformation of the p-value
and adds no information; the useful calculation is the *prospective* sample size.

**Step 5 — sample size.** For 1.4 pp absolute lift (a realistic, decision-relevant effect),
Cohen's h = 0.074 and the required per-arm sample is about 2,903. The current test has 400.
For the 2.39 pp lift actually observed, about 2,270 per arm would be needed. The practical
implication: run for three to four weeks, not three days.

**Step 6 — subgroups.** Desktop: A 11.86 %, B 13.90 %. Mobile: A 4.87 %, B 7.14 %. Both
favour B, and the relative lift is similar (17 % and 47 %). Two subgroup tests were
performed; with Bonferroni the threshold is 0.025, and neither reaches it. The consistency
of direction is reassuring but is not evidence of significance; reporting "B works better
on mobile" would be over-reading.

**Step 7 — the decision.** Shipping B on a 30 % point estimate is a gamble with a real
chance of being wrong: the interval includes zero and the expected loss if B is worse is
not negligible. The disciplined options are (i) continue the test to 2,900 per arm, or
(ii) ship B as a limited rollout with monitoring, accepting that the effect is unproven.
Either is defensible; "B is 30 % better, ship it" is not.

**Peeking warning.** If the analyst had checked the data daily and stopped at the first
p < 0.05, the false-positive rate would be far above 5 %. Pre-register the sample size or
use a sequential design with adjusted boundaries; do not test repeatedly and stop when
convenient.

**Why randomisation matters here.** Observed differences in real traffic are confounded by
seasonality, campaign timing and user mix. Random assignment is what licenses the causal
reading "B causes higher conversion"; the statistical test only quantifies the noise.
