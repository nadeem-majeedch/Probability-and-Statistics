# Case studies

Twenty-four scenario-based case studies that apply the course to realistic problems. Each
one follows the same twelve-part structure — problem statement, background, dataset,
questions, concepts, formulation, analytical approach, student tasks, Python
implementation, visualisation, expected conclusions, and a detailed solution — so you can
work through them in any order, at any level.

!!! warning "All data are synthetic"
    Every dataset here was generated by `tools/generate_case_data.py` with a documented
    mechanism and a fixed seed. Nothing is real data, and no result is an empirical finding
    about students, patients, customers or machines. The point is the reasoning, not the
    numbers. See the [dataset notes](../data/case-studies/README.md) for the generating
    mechanism of each file.

## How to use a case study

1. Read sections **A–D** and write down what you think the answer will be.
2. Skim **E–F**; if a concept is unfamiliar, follow the module link at the top of the page.
3. Work through **G–H** on your own before looking at **I**.
4. Run the Python in section **I**. Change something — a seed, a threshold, a cost — and see
   what moves.
5. Compare your conclusions with **K**, then read **L** for the full derivation and the
   mistakes to avoid.

Each page loads its data with a path relative to the repository root, so run Jupyter from
the repository root (or edit the path). Nothing needs to be downloaded: the CSVs are in
`docs/data/case-studies/` and are also linked from every page.

## The three levels

| Level | What it asks of you | Typical tools |
|---|---|---|
| **Easy** | Summarise, describe, compute one or two standard statistics | means, SD, IQR, correlation, 2 × 2 tables, t-tests |
| **Intermediate** | Model, test, quantify uncertainty, interpret a decision | confidence intervals, proportion tests, logistic and linear regression, control charts |
| **Advanced** | Separate competing explanations, validate a model, reason about assumptions | multiple regression, GLMs, ROC and calibration, simulation, confounding |

## Reproducibility

- All datasets are generated by `tools/generate_case_data.py` with fixed seeds; running it
  again reproduces every file.
- Every Python block in every case study is executed by `tools/check_case_studies.py`,
  which fails if a block raises an error, if a dataset link is broken, or if a page is
  missing one of the twelve sections.
- The numbers quoted in sections K and L are computed from these files. If you change a
  generator, expect the prose to need updating — the validator cannot check prose, so
  re-read section K whenever a dataset changes.
