## A. Problem statement

An online retailer has 2,572 transactions from 500 customers over one month, with a
customer segment (new, returning, VIP), basket size and spend. The analytics team must
quantify customer value by segment, model the distribution of transaction counts per
customer, estimate average basket size with a bootstrap interval, and advise on where
retention spending would earn the most.

## B. Background and context

Customer analytics is where discrete and continuous distributions meet: visits are counts
(Poisson-like), basket values are positive and right-skewed (lognormal-like), and customer
lifetime value is a product of frequency and monetary value. The mean basket is unstable
because a single large order moves it, so analysts use medians and bootstrap intervals. The
segment comparison is observational — VIPs are selected for their spending — so the case
also rehearses the discipline of not reading a segment difference as a causal effect of
upgrading someone to VIP.

## C. Dataset description

`transactions.csv` has 2,572 rows.

| Column | Type | Description |
|---|---|---|
| `customer_id` | integer | 1–500 |
| `segment` | text | `new`, `returning`, `vip` |
| `transaction_no` | integer | Visit number for that customer |
| `items` | integer | Items in the basket, 1–5 |
| `amount` | float | Order value |
| `category` | text | `grocery`, `electronics`, `fashion` |
| `day` | integer | Day of month, 1–30 |

**Generation method.** Each customer is assigned a segment (50 % new, 40 % returning, 10 %
VIP) and makes a Poisson(4)+1 number of visits. Basket items are uniform 1–5, and the
amount is lognormal with median \(35\times m_s\times\text{items}\) where \(m_s\) is 1.0 (new),
1.3 (returning) or 2.2 (VIP), with log-SD 0.5. Category is multinomial (grocery 0.6,
electronics 0.2, fashion 0.2). The data therefore have a known frequency-severity
structure that students can verify.

## D. Questions to investigate

1. How many transactions per customer, and is the count Poisson-like?
2. What is the distribution of basket amounts? Mean, median, skewness.
3. How do segments differ in average basket and in revenue contribution?
4. What is the average customer value (revenue per customer) by segment?
5. What is a 95 % bootstrap confidence interval for the mean basket?
6. How much does basket size (items) explain order value?
7. Where should retention spending go, and what would you need to know to decide?

## E. Relevant probability and statistical concepts

- Mean, median and skewness for monetary data.

- Simple regression and \(R^2\) for basket size.

## F. Mathematical formulation

Transactions per customer \(N_i\sim\mathrm{Poisson}(\lambda)\) has
\(E[N]=\mathrm{Var}(N)=\lambda\).

Basket amount \(A\) is lognormal with median \(m\) and log-SD \(\sigma\):

\[
E[A]=m\,e^{\sigma^2/2},\qquad
\mathrm{Var}(A)=m^2e^{\sigma^2}\left(e^{\sigma^2}-1\right).
\]

Revenue per customer in segment \(s\) is \(E[N_s]\,E[A_s]\), and total revenue share is

\[
\frac{n_s\,E[N_s]\,E[A_s]}{\sum_{s'} n_{s'}\,E[N_{s'}]\,E[A_{s'}]}.
\]

The nonparametric bootstrap resamples transactions with replacement \(B\) times and uses the
empirical 2.5th and 97.5th percentiles of the resampled means.

## G. Step-by-step analytical approach

1. Validate the file: transactions per customer, amount ranges, segment shares.
2. Compare the count distribution with Poisson via mean and variance.
3. Summarise basket amounts overall and by segment; note skewness.
4. Compute revenue and revenue per customer by segment.
5. Bootstrap the mean basket (1,000 resamples) and compare with the CLT interval.
6. Fit amount ~ items; report slope and \(R^2\).
7. Test whether segment differences in basket are statistically significant.
8. Write the retention recommendation with its observational caveat.

## I. Python practical implementation

```python
import numpy as np
import pandas as pd
from scipy import stats
import statsmodels.formula.api as smf

tx = pd.read_csv("docs/data/case-studies/transactions.csv")
print(tx.head(3).to_string(index=False))
print(f"transactions: {len(tx)}, customers: {tx.customer_id.nunique()}, "
      f"segments: {tx.segment.value_counts().to_dict()}")

per_customer = tx.groupby("customer_id").size()
print(f"\ntransactions per customer: mean={per_customer.mean():.2f}, "
      f"variance={per_customer.var(ddof=1):.2f}, "
      f"VMR={per_customer.var(ddof=1) / per_customer.mean():.2f}")

amount = tx.amount
print(f"\nbasket: mean={amount.mean():.2f}, median={amount.median():.2f}, "
      f"sd={amount.std(ddof=1):.2f}, skew={stats.skew(amount):.2f}")

segment_table = tx.groupby("segment").agg(
    customers=("customer_id", "nunique"),
    transactions=("amount", "size"),
    revenue=("amount", "sum"),
    mean_basket=("amount", "mean"),
    median_basket=("amount", "median"),
).round(2)
segment_table["revenue_per_customer"] = (
    segment_table.revenue / segment_table.customers).round(2)
segment_table["revenue_share"] = (segment_table.revenue / segment_table.revenue.sum()).round(3)
print("\nsegment table:")
print(segment_table.to_string())

rng = np.random.default_rng(42)
boot_means = np.array([
    rng.choice(amount.values, size=len(amount), replace=True).mean()
    for _ in range(1000)
])
lo, hi = np.percentile(boot_means, [2.5, 97.5])
clt_lo = amount.mean() - 1.96 * amount.std(ddof=1) / np.sqrt(len(amount))
clt_hi = amount.mean() + 1.96 * amount.std(ddof=1) / np.sqrt(len(amount))
print(f"\nbootstrap 95% CI for mean basket: [{lo:.2f}, {hi:.2f}]")
print(f"normal-theory 95% CI:             [{clt_lo:.2f}, {clt_hi:.2f}]")

model = smf.ols("amount ~ items", data=tx).fit()
print(f"\namount ~ items: slope={model.params['items']:.2f}, "
      f"R2={model.rsquared:.3f}")
print(f"correlation(items, amount) = {np.corrcoef(tx['items'], tx.amount)[0, 1]:.3f}")

new = tx.loc[tx.segment == "new", "amount"]
vip = tx.loc[tx.segment == "vip", "amount"]
print(f"\nnew vs vip basket: Welch p = {stats.ttest_ind(vip, new, equal_var=False).pvalue:.2e}")
print("category shares:", tx.category.value_counts(normalize=True).round(3).to_dict())
```

## L. Detailed solution and discussion

**Step 1 — counts.** Mean 5.14, variance 4.47. VMR ≈ 0.87, slightly under-dispersed but
close enough to 1 that a Poisson model is a reasonable first approximation. Under-dispersion
occurs here because visits were generated as Poisson and customers were capped by the
observation window; with real data, over-dispersion is more common and a negative binomial
would be needed.

**Step 2 — baskets.** Mean 148.23 against median 117.60: the gap of 30 is the skew (2.21,
which is substantial). The
standard deviation (121.31) is 82 % of the mean, so a normal model would produce negative
amounts — never use a normal interval for raw monetary data; use a log transform or the
bootstrap.

**Step 3 — segments.** Mean baskets rise across segments (123.66 → 153.79 → 247.58). The
Welch test between new and VIP gives p < 10⁻²⁰, so the difference is real in this sample.
But revenue per customer is the decision-relevant number: VIP 1,286, returning 794, new 633.
VIPs are 10 % of customers and 15 % of revenue — high value per head, limited scale.

**Step 4 — bootstrap.** The 1,000-resample interval is 143.49–153.00, mean 148.23. The
normal-theory interval (143.54–152.91) is almost identical here because the sample is large
(2,572); the bootstrap is marginally wider because it does not assume symmetry. Its real
advantage is that it can interval-ise any statistic (median, 90th percentile, revenue per
customer) without new theory. Resampling customers rather than transactions would be more appropriate for
inference about customer-level value, because transactions within a customer are not
independent.

**Step 5 — basket size.** Amount = −0.22 + 49.37 × items, \(R^2 = 0.337\). Each extra item
adds about 49 units of spend. The intercept near zero is sensible: an empty basket costs
nothing. The remaining 66 % of variance comes from the segment multiplier and lognormal
noise, which is why item count alone cannot predict order value well.

**Step 6 — where to spend.** The naive answer is "VIPs", but VIPs are already the best
customers — retention spending on them may be redundant. The higher-leverage group is
returning customers with above-median frequency and basket, who have demonstrated intent but
not yet loyalty. A proper analysis would model the probability of a second purchase
(retention) separately from basket size, and would use a randomised campaign to estimate the
causal effect of an incentive.

**Step 7 — selection warning.** Segment is not randomly assigned: VIP status is earned by
spending, so the 247.58 mean basket partly reflects the selection that created the segment.
"Do VIPs spend more?" is answered by these data; "would making someone VIP increase their
spending?" is not. That requires a controlled experiment, the design discussed in case
study I7.

**Data note.** The transaction count per customer is generated as Poisson(4)+1, so the
minimum is 1 by construction — every customer in the file is an observed buyer, and
non-buyers are absent. This is a truncation that biases average value upward relative to the
full population of visitors, a common issue in transactional datasets.
